# RFC-005: Cryptographic Identity & Signed Events Specification

## 📋 Status: PROPOSED / OPEN FOR REVIEW (Stage 1.5 / Transparency Log Architecture)

This specification defines the cryptographic authorization and digital signature model for the GreyMisnomer protocol, transforming `events.jsonl` from an untrusted single-writer log into a mathematically tamper-proof **Cryptographic Transparency Log** modeled after Certificate Transparency (RFC 6962) and Sigstore Rekor.

### Implementation Coverage
- [ ] Ed25519 public key identity (`PubKey`) and 64-byte detached signatures (`Signature`)
- [ ] Canonical, domain-separated binary signing preimages (anti-malleability)
- [ ] Monotonic account nonces for anti-replay protection
- [ ] VVB attestation verification for credit minting (`mint`)
- [ ] Asset owner cryptographic authorization for transfers (`transfer`) and retirements (`burn`)
- [ ] Invariant 8: Cryptographic Signature & Nonce Enforcement in pure `apply(state, event)`
- [ ] Sequencer Signed Log Head (SLH / Checkpoint)

### Reference Implementation Targets
- `src/core/src/identity.rs`
- `src/core/src/signature.rs`
- `src/core/src/registry.rs`
- `src/core/src/event_log.rs`

## 1. Problem Statement

RFC-004 established an append-only, hash-chained ledger (`events.jsonl`) that proves historical continuity and thermodynamic timestamping via OpenTimestamps. Furthermore, pure `apply(state, event)` deterministically enforces seven core accounting invariants (serial disjointness, authorized supply limits, Merkle data root deduplication).

However, forensic analysis reveals a **fundamental authorization gap**:

1. **Unauthenticated String Identities:** Asset owners are currently represented as arbitrary, unauthenticated strings (e.g., `"0xProjectOwner"`, `"ABC Solar Energy"`, `"BuyerOrg"`).
2. **Sequencer God-Mode Vulnerability:** Because `apply()` verifies structural and semantic constraints but **does not verify digital signatures**, any entity capable of appending a line to `events.jsonl` (a repository maintainer, a compromised GitHub Actions workflow, or a rogue sequencer) can inject an unauthorized transaction:
   ```json
   {
     "seq": 4,
     "prev_hash": "c17a82528808ad7d46ae03510100b84463a49a1ed3f6abc0fee27c24f75377f9",
     "type": "transfer",
     "payload": {
       "credit_id": "CC-SOLAR-001",
       "new_owner": "attacker_wallet"
     },
     "hash": "..."
   }
   ```
   The existing `apply()` state machine would accept this transfer as valid because `CC-SOLAR-001` exists and is active, permanently depriving the legitimate owner of their carbon credits without their cryptographic consent.
3. **The Bitcoin Lesson:** In Bitcoin Core, a transaction is invalid unless it satisfies the cryptographic `scriptPubKey` via an ECDSA/Schnorr signature matching the coin's public key. The database, networking, and consensus layers cannot bypass this cryptographic authorization check.

> [!CRITICAL]
> **The Requirement:** The maintainer or sequencer must be demoted to an **untrusted ordering service**. The sequencer must possess **zero mathematical capability to mint, reallocate, or destroy credits** without detached cryptographic signatures issued by the private keys of the asset owner or accredited validator.

## 2. Proposed Solution: The Cryptographic Transparency Log

GreyMisnomer adopts the **Signed Transparency Log** paradigm (pioneered by Certificate Transparency / RFC 6962 and Sigstore Rekor):

```
┌────────────────────────────────────────────────────────────────────────┐
│                        ACTORS & KEYPAIRS                               │
│                                                                        │
│   [ Accredited VVB ]            [ Credit Owner ]      [ Sequencer ]    │
│    (Private Key: sk_vvb)         (Private Key: sk_own) (Key: sk_seq)   │
│           │                             │                   │          │
│           ▼                             ▼                   ▼          │
│   Signs PoI Attestation         Signs Transfer/Burn  Signs Log Head    │
└───────────┬─────────────────────────────┬───────────────────┬──────────┘
            │                             │                   │
            ▼                             ▼                   │
┌─────────────────────────────────────────────────────────┐   │
│               UNTRUSTED SEQUENCER (Git / PR)            │   │
│                                                         │   │
│   • Gathers signed transactions                         │   │
│   • Assigns contiguous sequence numbers (seq: 0, 1, 2)  │   │
│   • Computes BLAKE3 hash chain (prev_hash -> hash)      │   │
│   • Appends to events.jsonl                             │   │
└───────────────────────────┬─────────────────────────────┘   │
                            │                                 │
                            ▼                                 ▼
┌────────────────────────────────────────────────────────────────────────┐
│                   INDEPENDENT VERIFICATION ENGINE                      │
│                (Rust CLI & In-Browser WASM Nodes)                      │
│                                                                        │
│   For every line in events.jsonl:                                      │
│     1. Verify sequence contiguity & BLAKE3 hash chaining               │
│     2. Check Nonce (prevents signature replay attacks)                 │
│     3. Verify Ed25519 Signature against public key                     │
│     4. Apply pure state transition & evaluate 7 protocol invariants    │
│     5. Verify OpenTimestamps Bitcoin attestation                       │
└────────────────────────────────────────────────────────────────────────┘
```

1. **Identity as Public Key:** Every user, developer, buyer, and validator is identified exclusively by a 32-byte Ed25519 public key (`PubKey`).
2. **Explicit Detached Signatures:** Every transition carries a 64-byte Ed25519 signature over a strictly defined, canonical binary preimage.
3. **Untrusted Sequencer:** If the sequencer attempts to alter a transaction payload, forge a transfer, or remint a spent range, the cryptographic signature check fails immediately in all replayer nodes and browser WASM verifiers.
4. **$0 Infrastructure Cost:** Uses standard public key cryptography without gas fees, external RPCs, or proprietary cloud dependencies.

## 3. Detailed Technical Specification

### 3.1. Cryptographic Primitives

- **Algorithm:** Ed25519 (Edwards-curve Digital Signature Algorithm using SHA-512 and Curve25519), conforming strictly to [RFC 8032](https://datatracker.ietf.org/doc/html/rfc8032).
- **Public Key Length:** 32 bytes (`[u8; 32]`). Serialized in JSON as a 64-character lowercase hexadecimal string (`ed25519:abcdef...`).
- **Signature Length:** 64 bytes (`[u8; 64]`). Serialized in JSON as a 128-character lowercase hexadecimal string.
- **Reference Rust Library:** `ed25519-dalek` (v2.x) with zero default features (`alloc` and `serde` enabled), guaranteeing constant-time verification, zero panics, and complete WebAssembly compatibility.

### 3.2. Account State & Anti-Replay Nonce Engine

To prevent signature replay attacks (where an attacker captures a valid transfer signature and re-submits it in a later block to transfer newly acquired credits), each public key maintains an account state within the registry:

```rust
#[derive(Default, Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct AccountState {
    /// Strictly monotonically increasing nonce (0, 1, 2, ...)
    pub nonce: u64,
}
```

- When an account authorizes a `transfer` or `burn`, the transaction MUST include `nonce == account.nonce`.
- Upon successful execution in `apply()`, `account.nonce` is incremented by 1.
- Any transaction submitted with an unexpected nonce is rejected with `RegistryError::BadNonce`.

### 3.3. Canonical Signing Preimage & Anti-Malleability

To guarantee that signatures cannot be malleated across different formats, platforms, or JSON serializations, signing preimages are constructed using **canonical length-prefixed binary encoding**, matching the design pattern established in RFC-003 §3.2.

Each preimage begins with an explicit 1-byte **Domain Separator**:

| Domain Byte | Constant | Operation |
|---|---|---|
| `0x10` | `DOM_MINT` | Validator attestation for credit issuance |
| `0x11` | `DOM_TRANSFER` | Owner authorization for credit transfer |
| `0x12` | `DOM_BURN` | Owner authorization for credit retirement |
| `0x13` | `DOM_LOG_HEAD` | Sequencer commitment to log tip |

#### 3.3.1. Transfer Signing Preimage (`0x11`)
```
Preimage = 
    0x11 (1 byte)
    || len(credit_id) (8 bytes big-endian u64) || credit_id (UTF-8 bytes)
    || current_owner_pubkey (32 bytes raw)
    || new_owner_pubkey (32 bytes raw)
    || nonce (8 bytes big-endian u64)
```

#### 3.3.2. Burn / Retirement Signing Preimage (`0x12`)
```
Preimage = 
    0x12 (1 byte)
    || len(credit_id) (8 bytes big-endian u64) || credit_id (UTF-8 bytes)
    || owner_pubkey (32 bytes raw)
    || burn_range.start (8 bytes big-endian u64)
    || burn_range.end (8 bytes big-endian u64)
    || len(beneficiary) (8 bytes big-endian u64) || beneficiary (UTF-8 bytes)
    || claim_type_tag (1 byte: 0x01=NetZero, 0x02=Compliance, 0x03=Payg)
    || nonce (8 bytes big-endian u64)
```

#### 3.3.3. VVB Mint Attestation Preimage (`0x10`)
```
Preimage = 
    0x10 (1 byte)
    || len(project_id) (8 bytes big-endian u64) || project_id (UTF-8 bytes)
    || len(credit_id) (8 bytes big-endian u64) || credit_id (UTF-8 bytes)
    || mrv_merkle_root (32 bytes raw BLAKE3 hash)
    || serial_range.start (8 bytes big-endian u64)
    || serial_range.end (8 bytes big-endian u64)
    || cc_mint_amount (8 bytes big-endian u64)
    || initial_owner_pubkey (32 bytes raw)
    || vvb_pubkey (32 bytes raw)
```

> [!IMPORTANT]
> The hash of this canonical binary byte string ($H = \text{BLAKE3}(\text{Preimage})$) is the exact payload signed by the actor's Ed25519 private key: $\text{Signature} = \text{Sign}_{sk}(H)$.

## 4. State Machine Verification Rules (`apply`)

The pure state transition function `apply(state, event) -> Result<RegistryState, RegistryError>` executes strict cryptographic verification prior to mutating state:

```rust
pub fn apply(state: &RegistryState, event: &RegistryEvent) -> Result<RegistryState, RegistryError> {
    match event {
        RegistryEvent::Mint { poi, owner } => {
            // 1. Verify VVB is in the accredited validator whitelist
            if !state.is_accredited_vvb(&poi.vvb_pubkey) {
                return Err(RegistryError::UnauthorizedValidator);
            }
            // 2. Verify VVB cryptographic signature over canonical mint preimage
            let preimage = build_mint_preimage(poi, owner);
            verify_ed25519(&poi.vvb_pubkey, &preimage, &poi.vvb_signature)?;

            // 3. Evaluate standard protocol invariants (1, 2, 3, 7)
            apply_mint(state, poi, owner)
        }
        RegistryEvent::Transfer { credit_id, current_owner, new_owner, nonce, signature } => {
            // 1. Assert credit exists and is currently owned by current_owner
            let credit = state.find_credit(credit_id)?;
            if credit.owner != *current_owner {
                return Err(RegistryError::OwnerMismatch);
            }
            // 2. Assert nonce matches expected account nonce
            let expected_nonce = state.get_account_nonce(current_owner);
            if *nonce != expected_nonce {
                return Err(RegistryError::BadNonce { expected: expected_nonce, found: *nonce });
            }
            // 3. Verify owner cryptographic signature over canonical transfer preimage
            let preimage = build_transfer_preimage(credit_id, current_owner, new_owner, *nonce);
            verify_ed25519(current_owner, &preimage, signature)?;

            // 4. Execute transfer and increment owner nonce
            apply_transfer(state, credit_id, new_owner, current_owner)
        }
        RegistryEvent::Burn { credit_id, owner, burn_range, beneficiary, claim_type, nonce, signature } => {
            // 1. Assert credit exists and is owned by owner
            let credit = state.find_credit(credit_id)?;
            if credit.owner != *owner {
                return Err(RegistryError::OwnerMismatch);
            }
            // 2. Assert nonce matches expected account nonce
            let expected_nonce = state.get_account_nonce(owner);
            if *nonce != expected_nonce {
                return Err(RegistryError::BadNonce { expected: expected_nonce, found: *nonce });
            }
            // 3. Verify owner cryptographic signature over canonical burn preimage
            let preimage = build_burn_preimage(credit_id, owner, burn_range, beneficiary, claim_type, *nonce);
            verify_ed25519(owner, &preimage, signature)?;

            // 4. Execute partial burn, issue PoO, and increment owner nonce
            apply_burn(state, credit_id, *burn_range, owner)
        }
    }
}
```

## 5. Security & Threat Model

| Threat Vector | Mitigation Strategy |
|---|---|
| **Sequencer Reallocation (Asset Theft)** | Sequencer cannot forge Ed25519 signatures. Any transfer missing the true owner's signature is rejected by all verifiers. |
| **Signature Replay** | Monotonic account nonces guarantee that every signed payload is uniquely bound to a single state transition and cannot be executed twice. |
| **Signature Malleability** | Enforces canonical RFC 8032 verification with strict scalar clamping and reject non-canonical representations ($S < L$). |
| **Preimage Confusion** | Length-prefixed binary layouts with 1-byte domain separation prefixes (`0x10`..`0x13`) ensure cross-action signature collisions are mathematically impossible. |
| **Fake Validator Attestation** | Minting strictly requires signatures from public keys registered in the governance VVB whitelist (`state.accredited_vvbs`). |

## 6. Implementation Roadmap

### Phase 1: Core Cryptographic Engine
1. Integrate `ed25519-dalek = { version = "2.1", default-features = false, features = ["alloc", "serde"] }` into `src/core/Cargo.toml`.
2. Implement `src/core/src/identity.rs` defining `PubKey` and `Signature` types.
3. Implement `src/core/src/signature.rs` defining binary preimage constructors and verification helpers.

### Phase 2: State Machine Integration
1. Extend `RegistryState` with `accounts: BTreeMap<PubKey, AccountState>` and `accredited_vvbs: BTreeSet<PubKey>`.
2. Update `apply()` to enforce signature and nonce verification as **Invariant 8**.
3. Update `src/core/src/event_log.rs` schema to serialize and parse signed events.

### Phase 3: Client Tooling & Verifiers
1. Extend `grey-misnomer-cli` with `keygen`, `sign-transfer`, and `sign-burn` commands.
2. Integrate WebCrypto API / `ed25519-dalek` in browser WASM for seamless client-side signing and verification.
3. Update Playwright E2E suite to test cryptographic rejection of tampered signatures.
