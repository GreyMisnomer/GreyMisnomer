# RFC-007: Core Performance Remediation, Hybrid UCO State Machine, RFC 9162 Merkle Tiles, C2SP Witness Cosigning & MRV Oracle Hardening

## 📝 Status: DRAFT (Proposed for Stages 3.5 – 4)

This specification defines the immediate hardening fixes to GreyMisnomer v1.3.0 alongside the v2.0 protocol upgrade to an **RFC 9162 verifiable transparency log with immutable static tiles**, a **hybrid Unretired Credit Output (UCO) state machine preserving explicit serial intervals**, **3-root light-client checkpoints**, **C2SP `tlog-cosignature` witness cosigning**, and a **hardened MRV oracle and buffer-pool governance model**.

## 1. Executive Summary & Scope

An independent systems audit of GreyMisnomer v1.3.0 combined with an architectural review of `RFC-GM-002` established three critical findings:

1. **The v1.3.0 baseline contains verified correctness, cryptographic, and performance defects** that must be fixed *before* introducing embedded databases (`redb`), peer-to-peer networking, or zero-knowledge proofs.
2. **Bitcoin's core security guarantees (no split views and permissionless data survival) do not require premature BFT or zkVM complexity.** Replacing the flat hash chain with an **RFC 9162-style Merkle tree log packaged as immutable static tiles** plus **C2SP `tlog-cosignature` witness cosigning** achieves non-equivocation ("one global history") and mirror independence immediately at \$0 SaaS cost.
3. **Naive UTXO and transport designs create subtle ecological and systems regressions.** Raw amount-only UTXOs would violate serial traceability (`RFC-002`), Bitcoin-style headers cannot prove non-spentness to SPV clients, Litecoin already claims ports `9332`/`9333`, and carbon registries fail primarily at the **MRV oracle boundary** rather than transaction throughput.

`RFC-007` establishes the exact, ordered technical specification resolving every one of these gaps while explicitly keeping the protocol **coinless** (zero native speculative currency; zero gas tokens; India VDA tax compliant per [RFC-004](rfc-004.md) and [Verra's 2022 double-counting halt](https://reccessary.com/en/news/Verra-halts-tokenization-of-carbon-credits-avoid-double-counting)).

## 2. Verified v1.3.0 Baseline Findings (Stage 3.5 Prerequisites)

Before writing a single line of storage (`redb`), P2P networking, or zkVM code, the following four verified baseline defects MUST be resolved.

### 2.1 Finding 1: Superlinear $\approx O(n^{2.4})$ Replay & State-Cloning Bottleneck

- **Observed Code:**
  - In [`src/core/src/event_log.rs`](../../src/core/src/event_log.rs) (`replay_log_with_anchor`), every iteration calls `state = apply(&state, &entry.event)?;` followed unconditionally by `state.check_invariants();`.
  - In [`src/core/src/registry.rs`](../../src/core/src/registry.rs), every `apply_*` handler (`apply_mint`, `apply_transfer`, `apply_burn`, `apply_vvb_register`, `apply_genesis`, etc.) clones the entire `RegistryState` (`let mut new_state = state.clone();`), copying every `CreditBatch`, `SerialRange`, `BTreeSet`, and `BTreeMap`.
  - Meanwhile, `check_invariants()` calls [`check_invariant_3`](../../src/core/src/registry.rs#L907-L924), [`check_invariant_4`](../../src/core/src/registry.rs#L928-L939), and [`check_invariant_5`](../../src/core/src/registry.rs#L943-L952), each containing $O(n^2)$ nested pairwise loops over all active and burned ranges, yielding $\approx O(n^3)$ asymptotic replay complexity (measured at `0.26s` for 1k mints, `6.5s` for 4k mints, and `40s` for 8k mints — empirically $\approx n^{2.4}$).
- **Mandatory Fix:**
  1. Introduce `apply_in_place(&mut state, &event) -> Result<TransitionDelta, RegistryError>` (or keep `apply(&state, event)` as a thin wrapper around `apply_in_place(&mut state.clone(), event)` for single-step pure API callers, while `replay_*` mutates a single owned `RegistryState` sequentially without cloning on every line).
  2. Stop running whole-state $O(n^2)$ `check_invariants()` on every intermediate event during sequential replay; verify incremental transition invariants in $O(1)$ / $O(\log n)$ during `apply_in_place`, and optimize standalone `check_invariants()` using sorted sweep-line range checks (`O(n \log n)`) rather than quadratic loops.
  3. Replace global scans at `Mint` time with **monotonic per-`(project_id, vintage_year)` serial allocation cursors** (turning serial-overlap verification from $O(n)$ into $O(1)$) and `BTreeMap<String, usize>` indexing (resolving Bug #16).

### 2.2 Finding 2: Stale Bitcoin `.ots` Proof & Existence-Only Verification

- **Observed Code:**

  - In [`src/cli/src/main.rs`](../../src/cli/src/main.rs#L1530-L1692), CLI checkpoint reporting checks only `ots_path.exists()` and prints `" [OTS: Bitcoin-Anchored ✅]"` without verifying the attested SHA-256 digest!
  - In [`docs/js/app.js`](../../docs/js/app.js#L1980-L1992), `checkOtsProof()` sends an HTTP `HEAD` request to `events.jsonl.ots` and prints `"Anchored in calendar pools"` merely on HTTP `200 OK`.
  - In [`.github/workflows/pages.yml`](../../.github/workflows/pages.yml#L87-L91), CI skips stamping whenever `events.jsonl.ots` exists (`ots upgrade || true`), leaving stale `.ots` proofs attached to modified logs.
- **Mandatory Fix:**
  1. Never assert `"Bitcoin-Anchored ✅"` on file existence alone. Add a deterministic `.ots` header/commitment digest parser inside `grey-misnomer-cli` (and WASM/JS UI) verifying that the `.ots` file's root file hash byte-for-byte equals `SHA-256(target_checkpoint_bytes)`.   2. Stamp **immutable checkpoints** (`.json` / canonical checkpoint note), never mutating append-only logs.
  3. Enforce `ots verify` (or deterministic digest + Bitcoin header proof verification) as a **blocking CI gate** in `.github/workflows/pages.yml`: any digest mismatch fails the build.

### 2.3 Finding 3: Predictable Public-String Key Derivation

- **Observed Code:**
  - [`src/cli/src/bin/generate_ledger.rs`](../../src/cli/src/bin/generate_ledger.rs#L17-L21) derives all five live alpha identities in `events.jsonl` from deterministic strings (`"authority-demo-key-2026"`, `"sequencer-demo-key-2026"`, `"vvb-tuv-nord-key-2026"`, `"tata-solar-project-owner-2026"`, `"infosys-corporate-buyer-2026"`).

  2. Remove name-to-secret derivation in `WasmRegistry::resolve_owner()`; all live key creation in CLI (`init`, `keygen`) and browser/desktop enclaves (`keystore.js`, UniFFI) MUST use OS/WebCrypto CSPRNG (`Keypair::generate()`) protected in encrypted `.gmkey` keystores.

Explicitly acknowledge a **clean cryptographic genesis break** for v2.0: rather than fabricating continuity over a compromised demo seed keyset and stale `.ots` proof, GreyMisnomer v2.0 initializes a fresh CSPRNG-rooted `chain_id_v2` Genesis while preserving the deterministic `v1.3 -> v2.0` state converter only as a migration test/importer utility.

## 3. Protocol Architecture: Hybrid UCO Model with Serial Intervals

### 3.1 Preserving `MICRO_UNITS_PER_CREDIT` and Explicit Serial Ranges

Per [RFC-001](rfc-001.md) and [RFC-002](rfc-002.md), carbon credits are **non-fungible across projects, methodologies, vintages, and serial ranges**. Replacing `CreditBatch` slices with an "amount-only" satoshi UTXO model (`amount: u64` without serial bounds) would quietly reintroduce fungible asset commingling.

Instead, every `UnretiredCreditOutput` (**UCO**) embeds an **explicit half-open serial interval** `[start_micro_unit, end_micro_unit)` measured in integer micro-units matching [`src/core/src/lib.rs`](../../src/core/src/lib.rs#L18-L19):

```rust
pub const MICRO_UNITS_PER_CREDIT: u64 = 1_000_000; // 1 credit (1 tCO2e / 1,000 kg) = 1,000,000 micro-units (1 gCO2e precision)
pub const MAX_UCO_MICRO_UNITS: u64 = 9_000_000_000_000_000; // <= 2^53 - 1 (JS MAX_SAFE_INTEGER guard; ~9B tCO2e)
pub const MAX_TX_OUTPUTS: usize = 16; // Coinless UCO fan-out anti-spam cap

#[derive(Debug, Clone, Copy, PartialEq, Eq, PartialOrd, Ord, Serialize, Deserialize)]
pub struct OutPoint {
    pub txid: [u8; 32], // Canonical BLAKE3 event/leaf ID of issuing or transfer transaction
    pub vout: u32,      // 0-based output index within that transaction
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct UnretiredCreditOutput {
    pub outpoint: OutPoint,
    pub batch_id: String,               // Deterministic batch identifier
    pub project_id: String,             // Registered project slug
    pub vintage_year: u16,              // Vintage year of sequestration/avoidance
    pub start_micro_unit: u64,          // Inclusive start of half-open interval [start, end)
    pub end_micro_unit: u64,            // Exclusive end (> start_micro_unit)
    pub micro_units: u64,               // Exact mass = end_micro_unit - start_micro_unit
    pub owner: PubKey,                  // Ed25519 owner verifying key
    pub op_index: u64,                  // Per-output monotonic counter (replay defense)
    pub methodology_hash: [u8; 32],
    pub mrv_data_root: [u8; 32],        // BLAKE3 Merkle root of MRV evidence (RFC-003)
    pub mrv_blob_mirrors: Vec<String>,  // Optional mirror hints (content verified via BLAKE3, not trusted by URL)
    pub challenge_until_epoch: u64,     // Pre-retirement dispute window end (0 if immediate / cleared)
    pub locked_escrow_program: Option<String>, // Optional Tier-2 statutory lock tag (Stage 6)
}
```

#### Hybrid UCO Transition Rules

1. **Monotonic Serial Cursor Allocation (`Mint`):**
   - State maintains `serial_cursors: BTreeMap<(String, u16), u64>` mapping `(project_id, vintage_year) -> next_unallocated_micro_unit`.
   - At `Mint`, the transaction MUST allocate strictly contiguously starting at `cursor` (`start_micro_unit == cursor`, `end_micro_unit == cursor + minted_micro_units`), advancing `cursor = end_micro_unit` in **$O(1)$** without scanning historical active or burned slices.
   - Conservation Guard: `end_micro_unit.checked_sub(start_micro_unit) == Some(minted_micro_units)`, `minted_micro_units > 0`, and `minted_micro_units <= MAX_UCO_MICRO_UNITS`.
2. **Contiguous Serial-Preserving Split / Transfer (`TransferSplit`):**
   - Inputs: $K \ge 1$ existing unretired `OutPoint`s signed strictly by each input owner, targeting `outputs` ($1 \le M \le \text{MAX\_TX\_OUTPUTS}$).
   - For a single-input split of interval $[A, C)$ into two outputs, Output 1 MUST cover $[A, B)$ and Output 2 MUST cover $[B, C)$ with $A < B < C$.
   - General multi-input rule: The multiset of half-open serial sub-intervals across outputs MUST be pairwise disjoint and form an exact bijective partition of the union of input serial intervals, guaranteeing:
     $$\sum_{i \in \text{In}} (in_i.\text{end} - in_i.\text{start}) == \sum_{j \in \text{Out}} (out_j.\text{end} - out_j.\text{start})$$
3. **Permanent Retirement (`BurnPoO`):**
   - Pre-condition: Current log epoch $\ge$ input's `challenge_until_epoch` (pre-retirement challenge window elapsed) and `locked_escrow_program.is_none()`.
   - Consumes the input UCO from `unspent_outputs` and inserts an immutable [`ProofOfOffsetCommitment`] into `poo_archive`:
     ```rust
     #[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
     pub struct ProofOfOffsetCommitment {
         pub consumed_outpoint: OutPoint,
         pub batch_id: String,
         pub project_id: String,
         pub vintage_year: u16,
         pub start_micro_unit: u64,
         pub end_micro_unit: u64,
         pub micro_units: u64,
         pub beneficiary: String,
         pub claim_type: ClaimType,
         pub retirement_epoch: u64,
         pub owner_sig: Signature,
     }
     ```
   - Supports partial retirement by atomically routing the retired sub-slice $[A, B)$ into `ProofOfOffsetCommitment` and emitting a change UCO $[B, C)$ back to the owner.

### 3.2 JavaScript `MAX_SAFE_INTEGER` Protection

Because JavaScript IEEE-754 floats lose precision above `Number.MAX_SAFE_INTEGER` ($2^{53}-1 = 9,007,199,254,740,991$):

1. Individual UCO quantities and per-event bounds MUST obey `micro_units <= MAX_UCO_MICRO_UNITS` (`9_000_000_000_000_000`, equal to $9\text{ billion tCO}_2\text{e}$).
2. All `greymisnomerd` Port `9482` JSON-RPC / WebSocket APIs MUST serialize `u64` fields (`start_micro_unit`, `end_micro_unit`, `micro_units`, `op_index`, `seq`) as **base-10 JSON strings** (or canonical decimal strings parsed via JS `BigInt`), while consensus hashing and signing ALWAYS operate on **canonical binary big-endian / `postcard` bytes**, never raw JSON text.

## 4. Verifiable Log Structure: RFC 9162 Merkle Log, 3-Root Checkpoints & Immutable Tiles

Rather than scanning a linear `hash_n = BLAKE3(hash_{n-1} || entry_n)` chain or downloading every historical line, GreyMisnomer v2.0 adopts a **verifiable Certificate Transparency architecture** combining **RFC 9162** Merkle log proofs, **3-root Checkpoint Headers**, and **immutable static tiles**.

```
                   ┌─────────────────────────────────────────┐
                   │   Signed & Cosigned Checkpoint Header   │
                   │  • origin, tree_size, timestamp         │
                   │  • events_root      (RFC 9162 Log Root) │
                   │  • uco_state_root   (Unspent UCO Root)  │
                   │  • poo_archive_root (Retired PoO Root)  │
                   │  • C2SP tlog-cosignature (k-of-n)       │
                   │  • OpenTimestamps (.ots over Checkpoint)│
                   └────────────────────┬────────────────────┘
                                        │
        ┌───────────────────────────────┼───────────────────────────────┐
        ▼                               ▼                               ▼
[Immutable Tiles Mirror]      [UCO Active State Merkle]      [PoO Burn Accumulator]
/tile/0/000, /tile/1/000      Sorted OutPoint leaves         Cumulative PoO leaves
O(log N) inclusion +          Proves UNSPENT / SPENT         Proves PERMANENT BURN
append-only consistency       without replaying history      for QR PDF certificates
Hosted on any dumb CDN / S3 / IPFS / Archive / Pages
```

### 4.1 Domain-Separated Cryptographic Hash Prefixes

Every hash computation across RFC-007 uses explicit domain separation matching RFC 6962 / RFC 9162 to prevent length-extension, leaf/internal confusion, and cross-tree replay attacks:

| Hash Target | Domain Separator Prefix | Purpose |
| :--- | :--- | :--- |
| **RFC 9162 Log Leaf** | `0x00 \|\| canonical_event_bytes` | Prevents leaf-vs-internal second-preimage attacks |
| **RFC 9162 Internal Node** | `0x01 \|\| left_hash[32] \|\| right_hash[32]` | Distinguishes branch nodes from leaves |
| **Active UCO State Leaf** | `"GM-v2-UCO:" \|\| canonical_uco_bytes` | Isolates active unspent credit commitments |
| **PoO Burn Commitment Leaf** | `"GM-v2-POO:" \|\| canonical_poo_bytes` | Isolates immutable Proof-of-Offset receipts |
| **Checkpoint Signing Note** | `"GM-v2-CHK:" \|\| canonical_header_bytes` | Domain-separates signed & `.ots`-anchored checkpoint headers |

### 4.2 Three-Root Checkpoint Header (Solving Bitcoin SPV's Blind Spot)

A standard Bitcoin SPV client proving a UTXO existed in Block 100 **cannot prove it was not already spent in Block 101** without downloading intermediate blocks. Every v2.0 GreyMisnomer Checkpoint Header resolves this directly by committing **three independent roots**:

```rust
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct CheckpointHeaderV2 {
    pub version: u16,                    // Protocol version = 2
    pub chain_id: [u8; 32],              // CSPRNG-rooted registry identifier
    pub tree_size: u64,                  // Total events committed (RFC 9162 log size)
    pub timestamp_ns: u64,               // Advisory sequencer UTC timestamp
    pub events_root: [u8; 32],           // RFC 9162 Merkle root of log events [0..tree_size)
    pub uco_state_root: [u8; 32],        // Merkle root of all currently UNSPENT UCOs (sorted by OutPoint)
    pub poo_archive_root: [u8; 32],      // Merkle root of all cumulative PoO retirements [0..retired_count)
    pub active_validators_hash: [u8; 32],// Hash of accredited VVB & witness quorum set
}
```

- **Log Consistency Proof (`events_root`):** $O(\log N)$ proof that Checkpoint $B$ is a pure append-only extension of Checkpoint $A$ (`tree_size_B >= tree_size_A`).
- **Active Unspentness Proof (`uco_state_root`):** $O(\log M)$ inclusion proof demonstrating an `OutPoint` is currently unretired as of `tree_size` (or non-inclusion proof demonstrating it has been spent).
- **Permanent Offset Proof (`poo_archive_root`):** $O(\log R)$ inclusion proof verifying a corporate Proof-of-Offset PDF certificate without replaying the global ledger.

### 4.3 Immutable Static Tile Layout (C2SP `tlog-tiles` Pattern)

Instead of mutating a monolithic `events.jsonl` file and invalidating caches on every write, log leaves and inner Merkle hashes are published as **fixed-width immutable tiles** (`TILE_WIDTH = 256`, tile height `8`):

- Raw leaf data tiles: `/tile/entries/<index>` (populated up to `256` canonical events; `.p/<partial>` only for the trailing active partial tile).
- Hash subtree tiles: `/tile/<level>/<index>` (`level 0` stores parent hashes over `256` leaves; full tiles are content-immutable forever).
- Checkpoint pointer: `/checkpoint` (tiny signed C2SP-compatible ASCII note or JSON referencing `CheckpointHeaderV2` + witness cosignatures + `.ots`).

Because completed tiles **never change**, any commodity static host — **GitHub (within read-only mirror bounds), S3/R2, IPFS, Archive.org, nginx, USB drive** — acts as an **untrusted dumb mirror** caching immutable files aggressively without ever holding trust authority.

## 5. C2SP Witness Cosigning & Staged Non-Equivocation

Full multi-round BFT state-machine consensus and FROST threshold DKG resharing introduce significant operational complexity before an institutional validator committee even exists. GreyMisnomer adopts **[C2SP `tlog-cosignature`](https://github.com/C2SP/C2SP/blob/main/tlog-cosignature.md)** as its immediate non-equivocation defense:

### 5.1 How C2SP Witness Cosigning Works

1. The log operator (sequencer) submits `(old_checkpoint, new_checkpoint, consistency_proof)` over HTTPS POST to $N$ independent **Witnesses** (e.g., an environmental NGO, an academic university lab, a grid monitor, an open-source foundation).
2. Each Witness stores only `(last_tree_size, last_events_root)` (~64 bytes per tracked registry). It checks deterministically:
   - Log signature validity on `new_checkpoint`.
   - `new.tree_size >= old.tree_size`.
   - The supplied $O(\log N)$ RFC 9162 **consistency proof** mathematically links `old.events_root` to `new.events_root`.
3. If valid, the Witness atomically updates its local checkpoint bookmark and returns a lightweight Ed25519 cosignature line stamped with current UNIX seconds:
   ```text
   — <witness-name> <key-id + 64-byte Ed25519 sig over cosignature/v1 + timestamp + note>
   ```
4. Verifier nodes (`grey-misnomer-cli`, `docs/app.html`, `greymisnomerd`, mobile SPV) **reject any checkpoint carrying fewer than $k$-of-$n$ valid distinct witness cosignatures**.

**Security Guarantee:** Even if the GitHub repository operator or sequencer compromises their own key and attempts to present a forked `events_root'` to Buyer Alice while showing `events_root` to Regulator Bob, witnesses holding `last_tree_size` refuse to cosign the conflicting branch, halting any split-view attack with zero heavy BFT state replication required.

*(When governance committees formally mandate single aggregated 64-byte signatures in later stages, FROST Ed25519 can optionally aggregate witness/committee approvals.)*

## 6. Hardened MRV Oracle Governance & Data Availability

Bitcoin has no external physical oracle; carbon registries live or die by the **truth of physical emissions reductions** ([RFC-001](rfc-001.md)). To harden the MRV ingestion boundary, `RFC-007` adds four protocol-enforced primitives:

1. **Multi-VVB Attestation Quorum ($k$-of-$n$):** High-value `Mint` events (or all statutory-tier mints) require $k$ independent accredited Validation & Verification Body (VVB) signatures (plus optional secondary hardware/satellite telemetry witness attestations) over the exact `mrv_data_root`. Single-auditor unilateral issuance is prohibited under quorum methodologies.
2. **On-Log VVB Accreditation & Revocation Lifecycle:** Accredited VVBs and oracle keys are recorded transparently as signed governance log events (`VvbRegister`, `VvbRevoke`) bounded to methodology scopes and expiration epochs.
3. **Mandatory Pre-Retirement Challenge Window (`challenge_until_epoch`):** Newly minted UCOs remain non-retirable (`BurnPoO` rejected with `ChallengeWindowActive`) for an epoch delay window after issuance. Independent auditors, NGOs, and automated remote-sensing verifiers fetch raw MRV evidence blobs during this window and verify claims before credits can be permanently retired against corporate Net-Zero claims.
4. **Revocation with Protocol Buffer Pool (`OracleSlash` / `BufferCompensate`):**
   - A designated **Buffer Pool Reserve** holds unretired buffer UCOs (e.g., 5–20% project buffer withholdings per methodology).
   - If fraud or reversal is proven and adjudicated (`RevokeWithBuffer`), disputed active UCOs are frozen/burned directly or matched against the buffer pool without retroactively invalidating unrelated downstream transactions or obscuring fraud provenance.
5. **Mirror-Agnostic Evidence Availability (Solving Hosted Relay Reliance):**
   - Raw MRV evidence bundles (audit PDFs, raw sensor CSV/JSON, geospatial boundaries) are committed by their **BLAKE3 Merkle root (`RFC-003`)** inside every `UcoMint`.
   - `RFC-007` mandates pinning across **at least 2 independent content-addressed or archival mirrors** (e.g., self-pinned IPFS / community Pinning node + Internet Archive / operator HTTP-CAS S3 mirror). URLs are treated purely as untrusted retrieval hints checked against BLAKE3 hashes; public rate-limited hosted `iroh` relays (run by n0) MUST NOT be treated as a censorship-resistant sovereign dependency unless self-hosted relays and direct QUIC peer fallbacks are configured.

## 7. Local Daemon Architecture (`greymisnomerd`) & SDK Alignment

In Stage 4, **`greymisnomerd`** (`src/daemon/`) launches first as an **autonomous tile mirror, cryptographic verifier, and monitor** before full P2P gossip/consensus complexity is layered in:

1. **Tile Sync & Full Verification Loop:** Polls or watches untrusted tile mirrors, downloads only new tiles since `local_tree_size`, verifies every RFC 9162 Merkle consistency proof, verifies $k$-of-$n$ C2SP witness cosignatures, verifies `.ots` SHA-256 digests against local/Bitcoin data, validates `apply_uco()`, and persists indexed state into embedded pure-Rust **`redb`**.
2. **Local JSON-RPC & Event Bus (`127.0.0.1:9482`):** Serves verified state via HTTP/WebSocket (`GET /v1/chain/status`, `GET /v1/uco/:outpoint`, `GET /v1/proof/spv/:outpoint`, `GET /v1/proof/poi/:root`, `GET /v1/checkpoint/latest`, `WS /v1/events/subscribe`) with stringified `u64` numbers for JS safety and `.cookie` localhost auth.
3. **Unified SDK Strategy:** All clients — `grey-misnomer-cli`, `docs/app.html` (`grey-misnomer-wasm`), **Tauri v2** Desktop (macOS/Windows/Linux), and **UniFFI** Mobile SDK (Swift/Kotlin) — link against the identical **`grey-misnomer-core`** verification crate, optionally querying `127.0.0.1:9482` for instant indexed proofs while retaining full zero-trust client verification.
4. **Stage 4.5+ P2P Upgrade Path (`Port 9483`):** When peer-to-peer transaction gossip activates on Port `9483`, mempool relays MUST enforce `MAX_TX_OUTPUTS = 16`, per-owner epoch rate limits, and optional 16-bit BLAKE3 hashcash anti-spam stamps (`~20 ms` CPU cost, zero coin) to prevent `redb` UTXO bloat attacks.

## 8. Strategy, Execution Sequence & Open Governance Decisions

### 8.1 Institutional Strategy: CCTS Audit Log & Public Mirror Positioning

India's Bureau of Energy Efficiency (BEE) already operates the statutory **[Indian Carbon Market Portal](https://icapcarbonaction.com/en/news/compliance-obligations-under-indias-carbon-credit-trading-scheme-enter-force-seven-sectors)** under the Carbon Credit Trading Scheme (CCTS). Attempting to persuade a national ministry to rip-and-replace statutory infrastructure prematurely creates institutional friction.
